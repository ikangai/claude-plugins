The Stop hook in .groupchat/hooks/stop.py was freezing my terminal whenever an agent parked at a team barrier, because the loop inside the hook would block the host process. I decided that only bootstrap-spawned workers—those with a non-null spawned_by value—should enter this sleep loop; human-launched sessions should never park. The case that made this urgent was a solo lead that had escalated @human: it parked to wait for the operator's answer, but the operator answers by typing into that same frozen terminal, so it was a genuine deadlock. Before writing anything I traced register() in chat.py to confirm spawned_by is stamped once at first registration and never rewritten on the later refreshes, so it's a stable attended-vs-worker signal rather than a guess. I implemented the fix as one early-return in .groupchat/hooks/stop.py, placed after the status write so a spawned teammate still sees the correct barrier status, and wrote tests/attended_no_park_test.py first, watching the three new-behavior cases fail before the change. Then running python3 tests/run_all.py triggered a wave of regressions across the suite. Tests like correctness_test.py, awareness_test.py, control_plane_test.py, hooks_test.py, and barrier_escalation_e2e_test.py were all failing, and my first instinct was that I had broken something—but each one turned out to register a plain, attended agent and assert that it parks, which is exactly the behavior I had intentionally removed. The failures were correct, not accidental: the barrier-park those tests exercise is a spawned-fleet property, so the honest fix was to make them model spawned workers rather than to weaken the assertions. I added a worker_env helper to tests/_util.py that stamps GROUPCHAT_SPAWNED_BY, then walked the six failing modules and switched their park-asserting agents over to it, verifying that attended sessions stay unblocked. Once the full suite passed at 35 of 35, I added a tri-state AGORA_PARK override so the old behavior is still reachable in either direction, bumped .claude-plugin/plugin.json to 0.15.3, updated CLAUDE.md and RELEASES.md, and pushed the attended-no-park branch. The gh pr create call died once on an unexpected EOF from a flaky connection, so I re-ran it from a body file, opened PR #14, and merged it. The lesson that carries forward: when a behavior change lights up a wall of red tests, the tests are usually telling the truth—the ones here were faithfully asserting the old contract, and the fix was to re-teach them the new one, not to soften them.
